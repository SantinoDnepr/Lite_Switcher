# ТЗ: автопереключение раскладки (режимы и языковые пакеты)

Версия: 1.0 (проект). Дата: 2026-10-25.
Основание: `prompts/prompt003.md`, `prompts/kb003.md`. Обоснование решений и измерения: `docs/auto-switching-architecture.md` (дальше «Архитектура»).

## 1. Цель и область

Научить Lite Switcher переключать раскладку автоматически, по набранному слову, в двух режимах:

- **литературный**: обычный текст на языках, для которых в Windows установлена раскладка (сейчас ru, uk, en; дальше европейские);
- **программистский**: ключевые слова и операторы языка программирования, который пользователь включил явно (сейчас 1С, затем Rust, C++).

Третий вариант это ручной режим (как сейчас, только хоткеи). Языки литературные и программистские подключаются как независимые пакеты данных, без изменения кода.

Вне объёма (первая итерация): привязка языка программирования к приложению; автозамена по Enter и знакам препинания; автодополнение; исправление опечаток; выбор языка из контекста окна.

## 2. Термины

| Термин | Значение |
|---|---|
| Пакет | Папка с `pack.ini` и файлами данных одного языка |
| Литературный / программистский пакет | Пакет с `kind = literary` / `kind = programming` |
| Активный пакет | Включён в конфиге **и** в системе есть нужные раскладки |
| Слово | Последовательность физических клавиш (scancode + shift) между границами слова (`WordBuffer`) |
| Кандидат | Слово, отображённое в какую-либо раскладку (целиком или частями) |
| Гибридное слово | Слово, части которого записаны в разных раскладках (`ЕстьNull`, `#Область`) |
| Сигил | Начальный символ `#` (препроцессор) или `&` (директива компиляции) |
| Seed | Ручной список ключевых слов, директив и пар ru/en языка программирования |

## 3. Общие требования

- **Платформа**: Windows 10/11, Rust (как сейчас). Новые зависимости только `fst` и `memmap2` (и `criterion` для бенчмарков, как dev-зависимость).
- **Совместимость**: существующий `config.ini` работает без правок. Неизвестные ключи игнорируются, отсутствующие берутся по умолчанию. Режим по умолчанию после обновления: `manual`.
- **Независимость**: код `lite-switcher-lang` не содержит упоминаний конкретных языков; всё языковое поведение задаётся пакетом.
- **Правила проекта**: все видимые тексты через `Language\*.ini` на трёх языках (English, Russian, Ukrainian) с тестами полноты; каждое изменение записывается в `history.md` с повышением версии; коммиты только локальные.

## 4. Функциональные требования

### 4.1 Режимы

| № | Требование |
|---|---|
| FR-M1 | Режимов три: `manual`, `auto_literary`, `auto_programming`. В каждый момент активен ровно один |
| FR-M2 | В `manual` автозамена не выполняется; хоткеи ручной конвертации (слово, выделение, регистр) работают **во всех режимах** |
| FR-M3 | Режим хранится в `[common] mode`; смена в трее, в настройках или хоткеем сразу записывается в `config.ini`, а запущенные демон и настройки синхронизируются с файлом (как сейчас для `autoswitch`) |
| FR-M4 | Миграция: если в файле есть `autoswitch`, а `mode` нет, то `autoswitch = true` → `auto_literary`, `false` → `manual`. Ключ `autoswitch` после миграции не записывается |
| FR-M5 | Хоткей `toggle_autoswitch` (ключ сохраняется) переключает `manual` ↔ последний автоматический режим (если автоматического ещё не было, то `auto_literary`) |
| FR-M6 | Если выбран режим без активных пакетов (например `auto_programming` без включённых языков), поведение как в `manual`; в трее и настройках показывается пояснение |

### 4.2 Меню в трее

| № | Требование |
|---|---|
| FR-T1 | Пункт «Auto-switching» заменяется пунктом **«Mode»** с подменю из трёх взаимоисключающих пунктов: **«auto literary»**, **«auto programming»**, **«manual»**; текущий отмечен галочкой |
| FR-T2 | Остальные пункты («Settings...», «Exit») без изменений |
| FR-T3 | Тексты берутся из `Language\*.ini` и обновляются при смене языка интерфейса в конфиге |

### 4.3 Настройки

| № | Требование |
|---|---|
| FR-S1 | В Common / General поле **Mode** (выпадающий список из трёх режимов) вместо флажка «Auto-switching» |
| FR-S2 | Новая вкладка **«Literary language»**: список всех найденных литературных пакетов с флажками (включён / выключен). Для неактивных пакетов (нет раскладки) строка серая, флажок доступен, рядом причина «layout not installed». Итог: «Found N, active M» |
| FR-S3 | Новая вкладка **«Programming language»**: список найденных программистских пакетов с флажками; рядом перечислены нужные раскладки; неактивные (нет раскладки) серые с причиной |
| FR-S4 | Для списков показываются только данные манифестов; файлы данных не открываются |
| FR-S5 | Изменения вкладок записываются кнопкой Save (как остальные); смена языка интерфейса по-прежнему мгновенная |

### 4.4 Конфигурация (новые и изменённые ключи)

```ini
[common]
; manual | auto_literary | auto_programming
mode = manual

[literary_language]
; auto = все найденные пакеты, иначе коды через запятую: ru,uk,en
enabled = auto

[programming_language]
; id пакетов через запятую, например 1c; по умолчанию пусто
enabled =
```

- `[literary_language] enabled = auto` по умолчанию; значение «пусто» означает «ни одного».
- `[programming_language] enabled` по умолчанию **пусто** (языки программирования включаются только явно).
- Порядок в `[programming_language] enabled` = приоритет при конфликте (Архитектура, 7.6).
- Генерируемый `config.ini` содержит комментарии на отдельных строках (как сейчас).

### 4.5 Языковые пакеты

| № | Требование |
|---|---|
| FR-P1 | Две корневые папки рядом с exe (поиск как у `Language`: рядом с exe и выше, не более 5 уровней): `LiteraryLanguages\` и `ProgrammingLanguages\`. В каждой по папке на язык (`ru`, `uk`, `1c`...) |
| FR-P2 | В папке языка обязателен `pack.ini` (формат в разделе 6.1), остальные файлы данных перечислены в нём |
| FR-P3 | При старте и при перезагрузке конфига выполняется обнаружение: читаются **только** `pack.ini`. Пакет с ошибкой манифеста пропускается с записью в лог |
| FR-P4 | Литературный пакет **активен**, если включён и в системе есть хотя бы одна раскладка, чей идентификатор локали начинается с одного из `[layouts] match` |
| FR-P5 | Программистский пакет **активен**, если включён и установлены **все** раскладки из `[layouts] require` |
| FR-P6 | Файлы данных открываются (mmap) только у активных пакетов; у пакетов, переставших быть активными, закрываются. Неактивные пакеты остаются в списках настроек |
| FR-P7 | Открытие данных выполняется вне потока хука; готовый набор подменяется атомарно; поток хука не ждёт |
| FR-P8 | Проверка при открытии: версия формата (`format`), контрольные суммы файлов из манифеста, размеры. При несовпадении пакет пропускается с записью в лог, остальные работают |
| FR-P9 | Добавление нового языка = добавление папки с пакетом; изменения кода не требуются. Документ «как добавить язык» входит в поставку (этап 5) |

### 4.6 Литературный режим (детектор)

| № | Требование |
|---|---|
| FR-L1 | Кандидаты: слово отображается в каждую раскладку активных литературных пакетов; текущая раскладка тоже кандидат |
| FR-L2 | Каскад: правила (уникальные буквы пакета, запрещённые сочетания) → сумма триграмм → словарь (FST), словарь вызывается только при малом отрыве лучших кандидатов |
| FR-L3 | Замена только если лучший кандидат лучше текущей раскладки не менее чем на порог пакета (`[literary] switch_margin`); слово из словаря текущей раскладки никогда не меняется |
| FR-L4 | ru/uk: при ничьей решают уникальные буквы, затем триграммы, затем язык предыдущего слова (контекст живёт не более 30 с и сбрасывается при смене окна) |
| FR-L5 | Слова из `exceptions.txt` пакета, слова с цифрами и слова целиком из заглавных букв не меняются |
| FR-L6 | Минимальная длина слова: `[literary] min_word_len` (по умолчанию 3) |
| FR-L7 | Результат: текст в раскладке победившего кандидата и переключение раскладки окна на неё |

### 4.7 Программистский режим (детектор), язык 1С

| № | Требование |
|---|---|
| FR-G1 | Решение только по словарю: точное совпадение без учёта регистра (`case_sensitive = false` в манифесте). Без n-грамм |
| FR-G2 | Кандидаты: целиком в каждой из двух раскладок пакета + все разрезы «часть в A, часть в B» (Архитектура, 7.1) |
| FR-G3 | Правило композиции: `<слово из словаря> + <сегмент из latin_segments>` (и наоборот) считается словом (Архитектура, 7.2) |
| FR-G4 | Одноязычное слово: заменить текст и переключить раскладку окна на ту, в которой слово записано |
| FR-G5 | Гибридное слово и слова с сигилом (`#Область`, `&НаКлиенте`, `ЕстьNull`, `&НачалоПериода`...): заменить текст и **оставить раскладку окна прежней**, если она совпадает с раскладкой хотя бы одной значимой части результата (сигил не учитывается); иначе переключить на раскладку значимой части |
| FR-G6 | Слово, уже имеющееся в словаре в текущей раскладке, не меняется |
| FR-G7 | Регистр результата: регистр набранных клавиш сохраняется (результат не приводится к «каноническому» написанию). Опция канонического регистра вне объёма |
| FR-G8 | Граница токена: после последнего однозначного разделителя; неоднозначные клавиши (`.`, `,`, `;`, `'`, `[`, `]`) разбираются гипотезами «буква»/«разделитель» (Архитектура, 7.4). При неоднозначности без перевеса замены нет |
| FR-G9 | Сигилы `#` и `&` распознаются как начало токена независимо от того, в какой раскладке нажата клавиша (`№Область` → `#Область`) |
| FR-G10 | Слои словаря по приоритету: seed, платформа (MCP), публичный срез `.bsl`, локальный лексикон (необязательный). Флаги записи: `keyword`, `directive`, `preprocessor`, `platform`, `local`, `hybrid`, `no_convert` |
| FR-G11 | Несколько включённых программистских пакетов: порядок в `enabled` = приоритет; слово принимается, только если его нет в словаре пакета в текущей раскладке; конфликт при равном приоритете означает «не менять» |

### 4.8 Исполнение в демоне

| № | Требование |
|---|---|
| FR-X1 | Автозамена срабатывает на пробеле (первая итерация). Пробел задерживается и вставляется вместе с заменой |
| FR-X2 | Замена выполняется теми же средствами, что ручная конвертация (Backspace × N, Unicode-текст, переключение раскладки или нет, звук по настройке) |
| FR-X3 | Input gate: нажатия, пришедшие во время замены, ставятся в очередь и воспроизводятся после неё (максимум 200 мс); при превышении очередь сбрасывается без потери нажатий |
| FR-X4 | Откат: первое нажатие хоткея «convert word» сразу после автозамены возвращает исходный текст и раскладку; следующие нажатия продолжают штатный цикл |
| FR-X5 | Не срабатывать: окна из `ignored_apps`; поля паролей (`ES_PASSWORD` стандартных полей ввода); при зажатых Ctrl/Alt/Win; если буфер слова начат не с начала слова (был сдвиг каретки или клик мышью) |
| FR-X6 | При `log_level = debug` в лог пишутся режим, решение, причина и время обработки, **но не сами слова** |
| FR-X7 | Любая ошибка пакета или детектора не должна прерывать работу демона и ручных хоткеев |

| № | Требование | Проверка |

| NFR-1 | Обработка одного слова (до 40 клавиш), release: медиана ≤ 100 мкс, p99 ≤ 1 мс | бенчмарк (`criterion`) для ru+uk+en и для 1С |

| NFR-8 | Ложные срабатывания важнее пропусков: пороги выбираются по метрике FP (раздел 7) | тесты точности |

## 6. Форматы данных

### 6.1 `pack.ini`

| Секция | Ключ | Тип | Обязателен | Описание |
|---|---|---|---|---|
| `[pack]` | `kind` | `literary` \| `programming` | да | вид пакета |
| | `code` | строка | да | идентификатор; совпадает с именем папки |
| | `name` | строка | да | название в списках настроек (английское) |
| | `format` | число | да | версия формата данных (сейчас 1) |
| | `version` | число | да | версия содержимого |
| `[layouts]` | `match` | список | literary | префиксы локалей (`ru`, `de`) |
| | `require` | список | programming | все раскладки должны быть установлены |
| | `roles` | список `код:роль` | programming | `native` / `latin` |
| `[files]` | `words`, `ngram`, `exceptions` | имя файла | по виду | файлы данных |
| | `sha256_<ключ>` | hex | рекомендуется | контрольные суммы |
| `[literary]` | `alphabet`, `unique_letters`, `forbidden_bigrams`, `min_word_len`, `switch_margin`, `fold_yo` | | literary | параметры каскада |
| `[programming]` | `case_sensitive`, `sigils`, `latin_segments`, `separators` | | programming | параметры токенизации |

### 6.2 `words.fst`

- Структура: `fst::Map`, ключи это строки в нижнем регистре (Unicode simple lowercase; при `fold_yo = true` буква `ё` приводится к `е`), значение `u32`.
- Значение: биты 0–15 класс частоты (логарифмическая шкала, 0 = неизвестна), биты 16–23 резерв, биты 24–31 флаги: 24 `keyword`, 25 `directive`, 26 `preprocessor`, 27 `platform`, 28 `local`, 29 `hybrid`, 30 `no_convert`, 31 резерв.

### 6.3 `ngram3.bin`

- Заголовок: magic `LSNG`, `u16` версия формата, `u16` длина алфавита `A`, `u32` размер таблицы, затем алфавит в UTF-8 с длиной-префиксом.
- Таблица: `u8` × `(A+1)³` (индекс 0 это граница слова). Значение = округлённое `−log2 p · scale`, ограниченное 0…255; 255 означает «невозможно». Оценка слова = сумма значений (меньше значит лучше); символ вне алфавита делает кандидата невозможным.

### 6.4 `seed.txt` (вход `dictgen`)

Строка: `<русская форма>|<английская форма>|<флаги через запятую>`; пустая английская форма допустима; `;` в начале строки это комментарий. Примеры:

```
Процедура|Procedure|keyword
#Область|#Region|preprocessor
&НаКлиенте|&AtClient|directive
ЕстьNull||hybrid
```

## 7. Тестирование и приёмка

### 7.1 Модульные тесты (lite-switcher-lang)

- Манифесты: корректные, с ошибками, неизвестные ключи, нужные/ненужные раскладки.
- Обнаружение и активация: 10 литературных пакетов при 3 раскладках → активны 3; программистский пакет без одной из требуемых раскладок → неактивен.
- Загрузка и выгрузка: открытие/закрытие, битые и пустые файлы, неверная версия формата.
- Тесты без WinAPI: статические таблицы раскладок en/ru/uk (`KeyRenderer` для тестов), чтобы тесты шли на любой машине.

### 7.2 Точность

Метод: размеченные слова «правильно набраны» (ожидается `Keep`) и «набраны в неверной раскладке» (получаются отображением клавиш правильного слова в другую раскладку; ожидается `Replace` с исходным словом).

| Режим | Набор | Порог приёмки |
|---|---|---|
| Литературный | ≥ 20 000 слов на язык (частотные + трудные: короткие 3–4 буквы, слова ru/uk с общими буквами) | полнота ≥ 95 % для слов от 4 букв (≥ 90 % для 3 букв); ложные срабатывания на правильно набранных ≤ 0,1 %; ошибки ru↔uk ≤ 1 % |
| Программистский (1С) | все записи seed в 4 вариантах: верная раскладка, неверная раскладка, гибрид, разный регистр | 100 % верных решений |
| Программистский (1С) | повтор набора реального кода: не менее 1 млн токенов из `E:\1c`, набранных правильно | ложных замен ≤ 0,01 % токенов; на токенах seed и платформы 0 |

### 7.3 Производительность

Бенчмарки по NFR-1…NFR-4; результаты сохраняются в `docs/benchmarks.md`. При нарушении p99 ≤ 1 мс детектор переносится в рабочий поток (архитектура это допускает: `Detector` это `Send + Sync`, результат применяется только если буфер слова не изменился).
