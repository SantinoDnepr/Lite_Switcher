# ТЗ: автопереключение раскладки (режимы и языковые пакеты)

Версия: 1.1 (готово к реализации). Дата: 2026-10-26.
Основание: `prompts/prompt003.md`, `prompts/prompt004.md`, `prompts/kb003.md`. Обоснование решений, измерения и проверка готовности: `docs/auto-switching-architecture.md` (дальше «Архитектура»). Источники данных и лицензии: `docs/data-sources.md`.

Изменения версии 1.1 (по `prompt004.md` и проверке готовности): один язык программирования выбирается radio-кнопкой (FR-S3, FR-G11); группа из семи флажков в Troubleshooting (FR-S6, FR-X10); автозамена на Enter и знаках препинания при однозначном ответе (FR-X1, FR-X8, FR-X9); хоткей после автозамены продолжает цикл (FR-X4); пороги точности пересмотрены по замерам прототипа (7.2); этапы и тексты обновлены; добавлены требования к лицензиям и данным.

## 1. Цель и область

Научить Lite Switcher переключать раскладку автоматически, по набранному слову, в двух режимах:

- **литературный**: обычный текст на языках, для которых в Windows установлена раскладка (сейчас ru, uk, en; позже европейские);
- **программистский**: ключевые слова и операторы **одного выбранного** языка программирования (сейчас 1С; затем Rust, C++).

Третий вариант это ручной режим (как сейчас, только хоткеи). Литературные и программистские языки подключаются как независимые пакеты данных, без изменения кода.

Вне объёма (эта итерация): привязка языка программирования к приложению (идея принята, рассматривается позже); автодополнение; исправление опечаток; выбор языка по контексту окна.

## 2. Термины

| Термин | Значение |
|---|---|
| Пакет | Папка с `pack.ini` и файлами данных одного языка |
| Литературный / программистский пакет | Пакет с `kind = literary` / `kind = programming` |
| Активный пакет | Литературный: включён и есть нужная раскладка. Программистский: **выбран** и установлены все нужные раскладки |
| Слово | Последовательность физических клавиш (scancode + shift) между границами слова (`WordBuffer`) |
| Эпизод слова | Промежуток от первой клавиши слова до клавиши-триггера |
| Клавиша-триггер | Клавиша, на которой принимается решение: пробел, Enter, однозначный знак препинания |
| Однозначный разделитель | Клавиша, дающая **не букву в каждой** раскладке набора кандидатов |
| Нечистое слово | Слово, при наборе которого нажата клавиша с отмеченным флажком блокировки (FR-X10) |
| Кандидат | Слово, отображённое в какую-либо раскладку (целиком или частями) |
| Гибридное слово | Слово, части которого записаны в разных раскладках (`ЕстьNull`, `#Область`) |
| Сигил | Начальный символ `#` (препроцессор) или `&` (директива) |
| Seed | Ручной список ключевых слов, директив и пар ru/en языка программирования |

## 3. Общие требования

- **Платформа**: Windows 10/11, Rust (как сейчас). Новые зависимости: `fst` (0.4.x), `memmap2` (0.9.x), для бенчмарков `criterion` (dev-зависимость).
- **Совместимость**: существующий `config.ini` работает без правок; неизвестные ключи игнорируются, отсутствующие берутся по умолчанию. Режим по умолчанию после обновления: `manual`.
- **Независимость**: код `lite-switcher-lang` не содержит упоминаний конкретных языков; поведение задаёт пакет.
- **Правила проекта**: все видимые тексты на английском как основной язык и через `Language\*.ini` с переводами на Russian и Ukrainian (тесты полноты); каждое изменение записывается в `history.md` с повышением версии; коммиты только локальные.
- **Данные и лицензии**: в git только частотные срезы; локальный лексикон не коммитится никогда; данные лицензируются отдельно от кода (`docs/data-sources.md`); данные NC и без лицензии не используются.

## 4. Функциональные требования

### 4.1 Режимы

| № | Требование |
|---|---|
| FR-M1 | Режимов три: `manual`, `auto_literary`, `auto_programming`. Активен ровно один |
| FR-M2 | В `manual` автозамена не выполняется; хоткеи ручной конвертации (слово, выделение, регистр) работают **во всех режимах** |
| FR-M3 | Режим хранится в `[common] mode`; смена в трее, в настройках или хоткеем сразу записывается в `config.ini`, запущенные демон и настройки синхронизируются с файлом |
| FR-M4 | Миграция: если есть `autoswitch`, а `mode` нет: `true` → `auto_literary`, `false` → `manual`. После миграции `autoswitch` не записывается |
| FR-M5 | Хоткей `toggle_autoswitch` (ключ сохраняется) переключает `manual` ↔ последний автоматический режим (если автоматического не было, то `auto_literary`) |
| FR-M6 | Режим без активных пакетов (`auto_programming` без выбранного или без активного языка; `auto_literary` без активных литературных пакетов) работает как `manual`; в трее и настройках показывается пояснение |

### 4.2 Меню в трее

| № | Требование |
|---|---|
| FR-T1 | Пункт «Auto-switching» заменяется пунктом **«Mode»** с подменю из трёх пунктов: **«Auto literary»**, **«Auto programming»**, **«Manual»**; текущий отмечен галочкой, взаимоисключение обеспечивает программа |
| FR-T2 | Пункты «Settings...» и «Exit» без изменений |
| FR-T3 | Тексты берутся из `Language\*.ini` и обновляются при смене языка интерфейса |

### 4.3 Настройки

| № | Требование |
|---|---|
| FR-S1 | В Common / General выпадающий список **Mode** (три режима) вместо флажка «Auto-switching» |
| FR-S2 | Вкладка **«Literary language»**: все найденные литературные пакеты с флажками. Неактивный пакет (нет раскладки) показывается серым с причиной «layout not installed», флажок доступен. Итог: «Found N, active M» |
| FR-S3 | Вкладка **«Programming language»**: найденные программистские пакеты **radio-кнопками** (выбирается ровно один); рядом перечислены нужные раскладки; неактивный пакет серый с причиной; если пакетов нет, показывается пояснение |
| FR-S4 | Для списков показываются только данные манифестов; файлы данных не открываются |
| FR-S5 | Изменения записываются кнопкой Save; смена языка интерфейса по-прежнему мгновенная |
| FR-S6 | Вкладка **Troubleshooting**: группа **«Do not switch the keyboard layout if any keys have been pressed»** (русский: «Не переключать раскладку, если были нажаты клавиши») с семью флажками: **Backspace, Left arrow, Right arrow, Up arrow, Down arrow, Delete, Change layout**. Под группой подсказка, что флажки относятся только к автоматическому переключению |
| FR-S7 | Значения флажков по умолчанию: **все включены** (ложное переключение хуже пропущенного) |

### 4.4 Конфигурация (новые и изменённые ключи)

```ini
[common]
; manual | auto_literary | auto_programming
mode = manual

[literary_language]
; auto = все найденные пакеты, иначе коды через запятую: ru,uk,en
enabled = auto

[programming_language]
; id выбранного языка (один), например 1c; пусто = не выбран
selected =

[troubleshooting]
; автозамена пропускается для слова, если при его наборе нажата отмеченная клавиша
no_switch_if_backspace = true
no_switch_if_left = true
no_switch_if_right = true
no_switch_if_up = true
no_switch_if_down = true
no_switch_if_delete = true
no_switch_if_change_layout = true
```

- `[literary_language] enabled`: по умолчанию `auto`; пустое значение означает «ни одного».
- `[programming_language] selected`: по умолчанию **пусто**; значение это `code` пакета, неизвестное значение трактуется как «не выбран».
- Генерируемый `config.ini` содержит комментарии на отдельных строках (как сейчас).

### 4.5 Языковые пакеты

| № | Требование |
|---|---|
| FR-P1 | Две корневые папки рядом с exe (поиск как у `Language`: рядом с exe и выше, до 5 уровней): `LiteraryLanguages\` и `ProgrammingLanguages\`; в каждой папка на язык |
| FR-P2 | В папке языка обязателен `pack.ini` (формат 6.1), включая поля `license` и `sources` |
| FR-P3 | При старте и перезагрузке конфига читаются **только** `pack.ini`; пакет с ошибкой манифеста пропускается с записью в лог |
| FR-P4 | Литературный пакет **активен**, если включён и в системе есть раскладка, чья локаль начинается с одного из `[layouts] match` |
| FR-P5 | Программистский пакет **активен**, если он **выбран** в `[programming_language] selected` и установлены **все** раскладки из `[layouts] require` |
| FR-P6 | Файлы данных открываются (mmap) только у активных пакетов; у переставших быть активными закрываются; неактивные остаются в списках настроек |
| FR-P7 | Открытие данных выполняется вне потока хука; готовый набор подменяется атомарно; поток хука не ждёт |
| FR-P8 | Проверка при открытии: версия формата, контрольные суммы, размеры; при несовпадении пакет пропускается с записью в лог |
| FR-P9 | Добавление языка = добавление папки с пакетом; правки кода не требуются. Документ «как добавить язык» входит в поставку (этап 5) |
| FR-P10 | Выбор другой радио-кнопки или смена флажков применяется без перезапуска демона (после сохранения конфига) |

### 4.6 Литературный режим (детектор)

| № | Требование |
|---|---|
| FR-L1 | Кандидаты: слово отображается в каждую раскладку активных литературных пакетов; текущая раскладка тоже кандидат |
| FR-L2 | Каскад: правила (недопустимые клавиши внутри `en`-кандидата, уникальные буквы, запрещённые сочетания) → сумма триграмм → словарь (FST) |
| FR-L3 | Замена только если лучший кандидат лучше текущего не менее чем на `switch_margin` (при попадании в словарь `dict_margin`); слово из словаря текущей раскладки не меняется никогда |
| FR-L4 | ru/uk: при ничьей решают уникальные буквы, затем триграммы, затем язык предыдущего слова (контекст живёт не более 30 с, сбрасывается при смене окна) |
| FR-L5 | Слова из `exceptions.txt`, слова с цифрами и слова целиком из заглавных букв не меняются |
| FR-L6 | Минимальная длина слова: `[literary] min_word_len` (по умолчанию 3) |
| FR-L7 | Результат: текст в раскладке победившего кандидата и переключение раскладки окна на неё |
| FR-L8 | Границы слова: однозначный разделитель завершает слово и является триггером; неоднозначная клавиша (буква хотя бы в одной раскладке: `,` `.` `;` `'` `[` `]` `` ` ``) считается разделителем только при однозначном решении по гипотезе «разделитель» (Архитектура, 6.1) |
| FR-L9 | Условие качества данных: словарь каждого литературного пакета после очистки ≥ 30 тыс. словоформ (для uk требуется второй источник, `docs/data-sources.md`) |

### 4.7 Программистский режим (детектор), язык 1С

| № | Требование |
|---|---|
| FR-G1 | Решение только по словарю: точное совпадение без учёта регистра (`case_sensitive = false`). Без n-грамм |
| FR-G2 | Кандидаты: целиком в каждой из двух раскладок пакета + все разрезы «часть в A, часть в B» (Архитектура, 7.1) |
| FR-G3 | Правило композиции: `<слово из словаря> + <сегмент из latin_segments>` (и наоборот) считается словом. Гибриды сверх этого перечисляются в словаре (правило покрывает около 60 % по замеру) |
| FR-G4 | Одноязычное слово: заменить текст и переключить раскладку окна на ту, в которой слово записано |
| FR-G5 | Гибрид и слова с сигилом (`#Область`, `&НаКлиенте`, `ЕстьNull`, `&НачалоПериода`...): заменить текст и **оставить раскладку прежней**, если она совпадает с раскладкой хотя бы одной значимой части результата (сигил не учитывается); иначе переключить на раскладку значимой части |
| FR-G6 | Слово, уже имеющееся в словаре в текущей раскладке, не меняется |
| FR-G7 | Регистр результата: регистр набранных клавиш сохраняется (канонический регистр вне объёма) |
| FR-G8 | Границы токена: однозначные разделители (пробел, Enter, `(` `)` `=` `+` `-` `*` и клавиши без букв в обеих раскладках) завершают токен; неоднозначные клавиши (`.` `,` `;` `'` `[` `]`) обрабатываются гипотезами «буква»/«разделитель»; при отсутствии перевеса замены нет (Архитектура, 7.4) |
| FR-G9 | Сигилы `#` и `&` распознаются как начало токена независимо от раскладки, в которой нажата клавиша (`№Область` → `#Область`) |
| FR-G10 | Слои словаря по приоритету: seed, платформа (MCP), публичный срез `.bsl`, локальный лексикон. Флаги: `keyword`, `directive`, `preprocessor`, `platform`, `local`, `hybrid`, `no_convert` |
| FR-G11 | **Один** язык программирования: используется пакет из `[programming_language] selected`; других программистских пакетов в работе нет. Правила приоритета между языками не нужны |

### 4.8 Исполнение в демоне

| № | Требование |
|---|---|
| FR-X1 | Клавиши-триггеры: **пробел, Enter и однозначные знаки препинания** (FR-L8, FR-G8). Решение принимается синхронно в обработчике хука; при `Keep` клавиша проходит без изменений |
| FR-X2 | При `Replace` клавиша-триггер проглатывается (вместе с отпусканием и автоповтором), выполняется замена теми же средствами, что у ручной конвертации (Backspace × N, Unicode-текст, переключение раскладки или нет, звук по настройке), затем триггер вставляется заново |
| FR-X3 | Input gate: нажатия, пришедшие во время замены, ставятся в очередь и воспроизводятся после неё (максимум 200 мс); при превышении очередь сбрасывается без потери нажатий |
| FR-X4 | После автозамены хоткей «convert word» **продолжает цикл** со следующей раскладки списка; после полного круга слово возвращается в исходный вид. Отдельного отката нет |
| FR-X5 | Не срабатывать: окна из `ignored_apps`; поля паролей (`ES_PASSWORD` стандартных полей); при зажатых Ctrl/Alt/Win; если буфер слова начат не с начала слова (клик мышью, смена окна) |
| FR-X6 | При `log_level = debug` в лог пишутся режим, решение, причина и время обработки, **но не слова** |
| FR-X7 | Любая ошибка пакета или детектора не прерывает работу демона и ручных хоткеев |
| FR-X8 | Знак препинания вставляется после замены как Unicode-символ, отрисованный в **целевой** раскладке (`?` в en становится `,` в ru); физическая клавиша не повторяется |
| FR-X9 | Enter: при замене проглатывается и вставляется после неё как `VK_RETURN`; при `Keep` проходит без изменений |
| FR-X10 | Блокировка по флажкам Troubleshooting (Архитектура, 10.4): если при наборе слова нажата клавиша с отмеченным флажком, слово нечистое и автозамена для него не выполняется. Backspace и Delete при снятом флажке не блокируют (Backspace редактирует буфер, Delete не влияет); стрелки всегда сбрасывают буфер, а отмеченный флажок сохраняет «нечистоту» до следующей границы слова; Change layout определяется по изменению HKL окна в фокусе относительно начала слова. Ручные хоткеи флажками не блокируются |

| | `name` | строка | да | название в списках настроек (английское) |

| | `version` | число | да | версия содержимого |

| | `sources` | список | да | источники (например `FrequencyWords-2018:ru`) |

### 6.2 `words.fst`

- Структура: `fst::Map`; ключи строки в нижнем регистре (Unicode simple lowercase; при `fold_yo = true` буква `ё` приводится к `е`), значение `u32`.
- Значение: биты 0–15 класс частоты (логарифмическая шкала, 0 = неизвестна), биты 16–23 резерв, биты 24–31 флаги: 24 `keyword`, 25 `directive`, 26 `preprocessor`, 27 `platform`, 28 `local`, 29 `hybrid`, 30 `no_convert`, 31 резерв.

### 6.3 `ngram3.bin`

- Заголовок: magic `LSNG`, `u16` версия формата, `u16` длина алфавита `A`, `u32` размер таблицы, затем алфавит в UTF-8 с длиной-префиксом.
- Таблица: `u8` × `(A+1)³` (индекс 0 это граница слова). Значение = округлённое `−log2 p · scale`, ограниченное 0…255; 255 означает «невозможно». Оценка слова = сумма значений (меньше значит лучше); символ вне алфавита делает кандидата невозможным.

### 6.4 `seed.txt` (вход `dictgen`)

Строка: `<русская форма>|<английская форма>|<флаги через запятую>`; пустая английская форма допустима; `;` в начале строки комментарий. Примеры:

```
Процедура|Procedure|keyword
#Область|#Region|preprocessor
&НаКлиенте|&AtClient|directive
ЕстьNull||hybrid
```

### 6.5 Классы клавиш (`RenderTable`)

Для набора кандидатов по таблице отображения вычисляются классы клавиши: **буква** (даёт букву в каждой раскладке), **разделитель** (не буква в каждой), **неоднозначная** (буква хотя бы в одной). Таблица строится при старте и при изменении списка раскладок; формат в памяти `[раскладка][shift][scancode] → char` плюс класс клавиши.

## 7. Тестирование и приёмка

### 7.1 Модульные тесты (`lite-switcher-lang`, `lite-switcher-core`)

- Манифесты: корректные, с ошибками, неизвестные ключи, нужные и ненужные раскладки; поля `license`, `sources`.
- Обнаружение и активация: 10 литературных пакетов при 3 раскладках → активны 3; программистский пакет активен только если выбран и есть все раскладки.
- Загрузка и выгрузка: открытие/закрытие, битые и пустые файлы, неверная версия формата.
- Конфиг: миграция `autoswitch` → `mode`, `selected`, семь `no_switch_if_*` (по умолчанию `true`), круговой тест.
- Тексты: полнота трёх языковых файлов и использование ключей (уже есть).
- Тесты без WinAPI: статические таблицы раскладок en/ru/uk, чтобы тесты шли на любой машине.

### 7.2 Точность

Метод: размеченные слова «правильно набраны» (ожидается `Keep`) и «набраны в неверной раскладке» (клавиши правильного слова отображаются в другую раскладку; ожидается `Replace` с исходным словом). Слова, текст которых совпадает в обеих раскладках, из набора исключаются. Базовые значения прототипа (Архитектура, 6.3) приведены в скобках; реализация обязана их достичь или превзойти.

| Режим | Набор | Порог приёмки |
|---|---|---|
| Литературный, **частые слова** (топ-30 тыс. по частоте) | не менее 5 000 слов на язык, длина 3–12 | ложные срабатывания ≤ 0,05 % (прототип 0,000 %); полнота всего ≥ 90 % (92,5 %); 3 буквы ≥ 80 % (82 %); 4 буквы ≥ 85 % (89 %); ≥ 5 букв ≥ 90 % (91–95 %); каждая пара языков ≥ 80 % (83–99 %) |
| Литературный, **редкие слова** (ранг > 30 тыс., не из словаря) | не менее 5 000 слов на язык | ложные срабатывания ≤ 0,2 % (0,149 %); полнота ≥ 85 % для слов от 5 букв (89–96 %); для 3–4 букв только «не ухудшать ложные срабатывания» |
| Литературный, **реальный текст** | не менее 100 тыс. слов размеченного текста, набранного правильно | ложные срабатывания ≤ 0,05 % слов |
| Условие данных | для каждого языка | словарь ≥ 30 тыс. словоформ после очистки (FR-L9); порог частоты подбирается `eval` |
| Программистский (1С), seed | все записи seed в 4 вариантах: верная раскладка, неверная раскладка, гибрид, разный регистр | 100 % верных решений |
| Программистский (1С), реальный код | повтор набора не менее 1 млн токенов из `E:\1c`, набранных правильно | ложных замен ≤ 0,01 % токенов; на токенах seed и платформы 0 |

### 7.3 Производительность

Бенчмарки по NFR-1…NFR-4; результаты в `docs/benchmarks.md`. При p99 > 1 мс детектор переносится в рабочий поток (интерфейс `Detector` это `Send + Sync`; результат применяется, только если буфер слова не изменился).
