# Автопереключение раскладки: архитектурные решения

Версия 2 (2026-10-26). Статус: утверждена с учётом `prompts/prompt004.md`, проверена на реализуемость (раздел 12).
Исходные материалы: `prompts/prompt003.md`, `prompts/prompt004.md`, `prompts/kb003.md`.
Связанные документы: `docs/auto-switching-spec.md` (ТЗ), `docs/data-sources.md` (источники данных и лицензии).

Что изменилось относительно версии 1: один язык программирования вместо списка (radio); автозамена также на Enter и знаках препинания, если ответ однозначен; хоткей после автозамены продолжает цикл; группа флажков «не переключать, если были нажаты клавиши»; источники данных и политика коммита словарей; реальные замеры вместо оценок; раздел проверки готовности.

## 2. Что показали измерения

### 2.1 MCP-сервер `bsl-platform-context` (через `.mcp.json`, `java`, stdio)

| Запрос | Результат |
|---|---|
| `Процедура` | не найдено |
| `ЕстьNull` (метод) | не найдено |
| `Область` | первые 10 результатов это типы платформы (`ОбластьЗаголовкаДиаграммы`...); директивы `#Область` среди них нет |
| `СтрНайти` | найден (глобальный метод платформы) |

- Сервер отдаёт **платформенный API**: типы, глобальные методы, свойства, члены типов. **Ключевых слов языка, директив компиляции, препроцессора и функций языка запросов нет.**
- Имена только русские; английских синонимов платформы (`StrFind`...) нет.
- Нет операции «выдать всё»: только `search` (лимит 50) и `getMembers` по имени типа. Выгрузка требует обхода (поиск по префиксам, затем `getMembers`).
- Описания сигнатур неровные, но **имена** надёжны.

### 2.2 Выгрузки `.bsl` (`E:\1c`, остальные диски проверены)

Размеры: **28 418 файлов, уникальных по содержимому 9 528 (427 МБ)**. На `D:\my_tools` только 17 файлов открытого проекта (не учитываются).

Глобальная статистика (уникальные файлы, комментарии и строки отброшены): 12,47 млн токенов, 211 531 различных (без регистра); 21 654 токена покрывают 90 % вхождений, 54 126 покрывают 95 %, 139 012 покрывают 99 %; встретились ≥20 раз 35 044, ≥100 раз 8 298. Ключевые слова: русские формы 2,90 млн вхождений, английские формы 0,137 млн (**около 4,5 %**).

Статистика по проектам (папки второго уровня):

| Покрытие гибридов правилом «слово + латинский хвост» при списке из 5 / 10 / 20 / 40 хвостов | 46,1 % / 51,2 % / 55,8 % / **60,6 %** |

Что следует:
- **Английские формы реально используются** (`procedure` около 13 тыс. против 129 тыс. у `Процедура`; `&AtClient` около 5,9 тыс.; `#Region` около 5,3 тыс.): словарь содержит обе формы каждого ключевого слова и директивы.
- **Правило композиции покрывает только около 60 % гибридных вхождений** (остальное это латинский префикс + кириллица, цифры, подчёркивания и т. п.). Поэтому гибриды **перечисляются** в словаре (публичный срез и seed), а композиция лишь расширяет охват на неизвестные комбинации.
- **Идентификаторы конфигураций сильно различаются**: словарь, собранный по половине проектов, покрывает лишь 64–97 % вхождений остальных. Распознавание языка опирается на ядро (seed, MCP, директивы); частые идентификаторы конкретной базы это **локальный лексикон** пользователя.
- **«Проекты» не независимы.** 23 папки это 12–16 групп, а фильтр публичного среза должен считать **группы**, а не папки (2.4).

### 2.3 Сравнение источников

| Критерий | Файлы `.bsl` (E:\1c) | MCP `bsl-platform-context` | Ручной seed |
|---|---|---|---|
| Ключевые слова, директивы, `#Область`, `&НаКлиенте` | да, с частотой | **нет** | да (около 100–150 записей) |
| Английские формы | да, как используются | нет | да (пары ru/en явно) |
| Типы, методы, свойства платформы | только встретившиеся в коде | **да, полные и чистые** | нет |
| Частоты | да | нет | нет |
| Идентификаторы конкретной конфигурации | да (приватные данные) | нет | нет |
| Шум | высокий (копии, генерируемый код) | низкий | нулевой |
| Стоимость получения | дедупликация, токенизация, кластеризация: около 6 минут на проход | обход поиска (порядка тысяч запросов) | один раз вручную |
| Риск для публичного репозитория | **высокий** (коммерческий код) | низкий (имена из документации) | нет |

**Вердикт: оба источника плюс seed.** Seed определяет язык (ключевые слова, директивы, препроцессор, пары ru/en, латинские сегменты). MCP даёт полный чистый перечень имён платформы. Файлы `.bsl` дают частоты, гибриды, фактическое употребление и локальный лексикон.

### 2.4 Политика публичного среза (для GitHub)

- В репозиторий и релиз идёт **публичный слой**: seed + имена из MCP + токены из `.bsl`, которые есть в seed/MCP **или** встречаются в **не менее K независимых группах** (по умолчанию K = 3; группы строятся по доле общих файлов ≥ 50 %). При 12–16 группах и десятке крупных проектов публичный срез получится заметно меньше 63 тыс. токенов: размер фиксируется при сборке, а не обещается заранее.
- **Локальный лексикон** (идентификаторы из своих баз) строится `dictgen` на машине пользователя, лежит в `ProgrammingLanguages\1c\local\`, в `.gitignore`, **не коммитится никогда**; подключается вторым слоем с меньшим приоритетом.
- Лицензии литературных данных: `docs/data-sources.md`.

## 3. Общая схема

```
 клавиатура ─► LL-хук (поток демона)
                 │ клавиши слова (scancode+shift) ── WordBuffer (есть)
                 ▼
          клавиша-триггер? (Пробел, Enter, однозначный знак препинания)
                 │да                     └──нет──► продолжаем набор
                 ▼
          слово «чистое»? (флажки блокировки, 10.4)  ──нет──► пропускаем
                 │да
                 ▼
          Engine (режим из конфига)
           ├─ manual            → ничего
           ├─ auto_literary     → LiteraryDetector ─┐
           └─ auto_programming  → ProgrammingDetector┤  (один выбранный язык)
                                                     ▼
                                   Verdict { Keep | Replace{ text, layout? } }
                 ▼
          Replace: триггер проглочен → Backspace×N, текст, смена раскладки (или нет),
                   триггер вставлен заново → цикл хоткея продолжается
```

Используется из существующего кода: `core::word::WordBuffer`, `KeyStroke`, `core::layout` (`enumerate`, `resolve_layouts`, `key_to_char`), `core::i18n`, `daemon::inject`, механизм проглатывания клавиш хоткеев (`swallowed_vk`). Изменения существующего кода перечислены в 12.2.

### Модули

| Крейт / модуль | Содержимое | WinAPI |
|---|---|---|
| `lite-switcher-core` (есть) | конфиг, раскладки, буфер слова, i18n, хоткеи; новое: поля конфига, `RenderTable`, классы клавиш | да |
| **`lite-switcher-lang` (новый)** | `pack` (манифест, обнаружение, реестр), `format` (`words.fst`, `ngram.bin`), `literary`, `programming`, `Detector`, `KeyRenderer` | **нет** |
| **`lite-switcher-dictgen` (новый)** | сборка пакетов из корпусов, `.bsl`, дампа MCP, seed | нет |
| `lite-switcher` (демон) | `engine.rs`: хук ↔ реестр пакетов ↔ замена; подменю трея | да |
| `lite-switcher-settings` | вкладки языков, поле Mode, группа флажков | да |

Наброски интерфейсов (для согласования):

```rust
pub trait KeyRenderer { fn render(&self, key: &KeyStroke, layout: &Layout) -> Option<char>; }

pub struct WordContext<'a> {
    pub keys: &'a [KeyStroke],
    pub trailing: Option<&'a KeyStroke>,   // клавиша-триггер (пробел/знак), если есть
    pub current: &'a Layout,
    pub layouts: &'a [Layout],             // раскладки пакета
    pub previous: Option<&'a Previous>,    // язык предыдущего слова (ru/uk)
}

pub enum Verdict {
    Keep,
    /// `layout: None` - раскладку окна не менять
    Replace { text: String, layout: Option<Layout>, reason: Reason },
}

pub trait Detector: Send + Sync {
    fn decide(&self, ctx: &WordContext, renderer: &dyn KeyRenderer) -> Verdict;
}
```

## 4. Режимы и интерфейс

- Конфиг: `[common] mode = manual | auto_literary | auto_programming`. Старый ключ `autoswitch` читается один раз при миграции (`true` → `auto_literary`, `false` → `manual`) и больше не записывается. Режим по умолчанию после обновления: **`manual`**.
- Трей: «Auto-switching» заменяется пунктом **«Mode»** с подменю из трёх пунктов: «Auto literary», «Auto programming», «Manual» (галочка у текущего; взаимоисключение обеспечивает программа, так как меню Windows не имеет радио-пунктов).
- Хоткеи ручной конвертации работают **во всех режимах**. `toggle_autoswitch` (ключ сохраняется) переключает `manual` ↔ последний автоматический режим.
- Настройки: в Common / General поле **Mode**; вкладка **«Literary language»** (список пакетов с флажками); вкладка **«Programming language»** (**radio-кнопки**: выбирается ровно один язык); в **Troubleshooting** группа флажков «Do not switch the keyboard layout if any keys have been pressed» (10.4). Неактивные пакеты (нет нужной раскладки) серые с причиной.
- Конфиг:

```ini
[common]
mode = manual

[literary_language]
; auto = все найденные пакеты, иначе коды через запятую: ru,uk,en
enabled = auto

[programming_language]
; id выбранного языка (один), например 1c; пусто = не выбран
selected =

[troubleshooting]
; автозамена пропускается для слова, если при его наборе нажата отмеченная клавиша
no_switch_if_backspace = true
no_switch_if_left = true
no_switch_if_right = true
no_switch_if_up = true
no_switch_if_down = true
no_switch_if_delete = true
no_switch_if_change_layout = true
```

- Режим `auto_programming` без выбранного (или без активного) языка работает как `manual`; в трее и настройках показывается пояснение.
- **Привязка языка программирования к приложению** (например, `1cv8.exe` → 1С) отложена как «очень интересная идея»: архитектура её не исключает, так как выбранный язык это значение настройки, которое позже может зависеть от процесса активного окна.

### 5.2 Манифест `pack.ini`

```ini
[pack]
kind = literary
code = ru
name = Russian

[layouts]
```

(Ключи `match` и секция `[literary]` относятся к литературному пакету, `require`, `roles` и секция `[programming]` к программистскому; комментарии в реальном файле пишутся на отдельных строках. Пороги `switch_margin` и `dict_margin` подбираются `dictgen eval`.)

### 5.3 Обнаружение и активация

1. При старте и перезагрузке конфига сканируются обе корневые папки, читаются **только `pack.ini`**.
2. **Литературный пакет активен**, если он включён и в Windows есть раскладка, чья локаль начинается с `match`. Пример: найдено 10 пакетов, установлено 3 раскладки, активны 3, остальные 7 неактивны (манифест прочитан, данные не открыты).
3. **Программистский пакет активен**, если он **выбран** (`[programming_language] selected`) и установлены **все** раскладки из `require` (для 1С русская и английская).
4. Для активных пакетов открываются файлы данных (mmap); при деактивации закрываются. Загрузка в фоновом потоке, готовый набор подменяется атомарно (`Arc`); поток хука не ждёт.
5. Пакет с неподдерживаемым `format`, повреждённым файлом или неверной контрольной суммой пропускается с записью в лог.

## 6. Алгоритм литературного режима

Вход: клавиши слова, клавиша-триггер, текущая раскладка. Основа: `kb003.md`, проверена на прототипе (6.3).

1. **Кандидаты.** Слово отображается в каждую раскладку активных литературных пакетов; текущая раскладка тоже кандидат.
2. **Правила** (почти бесплатные):
   - кандидат в `en` недопустим, если внутри слова есть клавиши, дающие там не буквы (`[ ] ; , . \`` и апостроф вне словаря): это прямой признак неверной раскладки;
   - уникальные буквы: `і ї є ґ` только в `uk`, `ы э ъ ё` только в `ru`;
   - запрещённые сочетания (`ъы`, `ьь`...) делают кандидата невозможным.
3. **Триграммы.** Сумма квантованных логарифмов вероятностей по каждому кандидату; победитель должен превосходить текущий кандидат **не меньше чем на порог** (`switch_margin`; при попадании победителя в словарь порог ниже: `dict_margin`).
4. **Словарь (FST).** Если текущий кандидат есть в словаре, **не менять**. Слова из `exceptions.txt` не менять.
5. **ru против uk.** Ничья (одинаковые буквы) разрешается уникальными буквами, затем триграммами, затем языком предыдущего слова (контекст живёт не более 30 с и сбрасывается при смене окна).
6. **Когда срабатывать.** На клавише-триггере (10.1) и не раньше `min_word_len` (3) символов. Не менять слова с цифрами и целиком из заглавных букв; не срабатывать в `ignored_apps`, при зажатых Ctrl/Alt/Win и для «нечистых» слов (10.4).
7. **Принцип.** Ложное переключение хуже пропущенного: пороги выбираются по метрике ложных срабатываний.

### 6.1 Границы слова и знаки препинания

Клавиша **однозначный разделитель**, если в **каждой** раскладке набора кандидатов она даёт не букву (пробел; `!`, `:`, `/`↔`.`, `?`↔`,` и т. п. по физическим клавишам). Такая клавиша завершает слово и является триггером. Клавиша, дающая букву хотя бы в одной раскладке (`,`/`б`, `.`/`ю`, `;`/`ж`, `'`/`э`, `[`/`х`, `]`/`ъ`, `` ` ``/`ё`), **неоднозначна**: она считается разделителем только если гипотеза «разделитель» даёт однозначное решение (слово-кандидат найден в словаре); иначе она остаётся буквой слова. После замены разделитель вставляется как символ, **отрисованный в целевой раскладке** (`?` в en становится `,` в ru).

### 6.2 Данные: условия качества

- Словарь и триграммы строятся по списку, **очищенному по частоте** (порог выбирается `dictgen eval`; на прототипе 150 вхождений дал лучший результат), и по алфавиту пакета.
- **Украинского из FrequencyWords недостаточно** (98,6 тыс. слов с частотой ≥3, 13,4 тыс. с частотой ≥30; русского 132 тыс.). Условие приёмки пакета `uk`: не менее 30 тыс. словоформ после очистки, для чего добавляется второй источник (`docs/data-sources.md`).

### 6.3 Результаты прототипа (замер 2026-10-26)

Условия: списки FrequencyWords 2018 (en, ru, uk); пороги словаря и обучения по частоте; слова из букв алфавита, длина 3–12; по 5 000 слов на язык; набор в своей раскладке (ожидается «не менять») и в двух чужих (ожидается «вернуть исходное слово»); слова, чей текст совпадает в обеих раскладках (ru/uk без особых букв), исключены. Каскад: словарь «не менять» → невозможный кандидат → триграммы (`dict_margin` = 2, `switch_margin` = 10).

Выводы:

- Короткие слова (3 буквы) и пары ru↔uk слабее: для них нужны правила на уникальные буквы, контекст предыдущего слова и более крупный украинский словарь.
- Ограничения прототипа: только буквенные клавиши (без знаков препинания внутри слов и апострофа), без контекста и без правил уникальных букв, один набор порогов. Реализация обязана улучшить результат и измерять его инструментом `dictgen eval` (пороги приёмки в ТЗ, раздел 7.2).

## 7. Алгоритм программистского режима (1С)

Принципы: **только точное совпадение со словарём**, **без регистра** (1С нечувствительна), **без n-грамм** (идентификаторов слишком много, n-граммы дали бы ложные срабатывания). Используется один выбранный язык программирования (7.6).

### 7.1 Кандидаты и сегментация

Ключ слова `k0..kn`. Для двух раскладок пакета (`ru`, `en`) строятся: слово целиком в каждой раскладке; все разрезы «часть в A, часть в B» (`2·(n+1)` строк). Каждая строка ищется в словаре без регистра.

| Набрано | Кандидат | Результат |
|---|---|---|
| `№Область` (раскладка ru) | разрез после 1-й клавиши: `#`(en) + `Область`(ru) | `#Область`; раскладка остаётся ru |
| `?НаКлиенте` (Shift+7 в ru даёт `?`) | `&`(en) + `НаКлиенте`(ru) | `&НаКлиенте`; раскладка остаётся ru |
| `&Yfrkbtynt` (всё в en) | `&` + `НаКлиенте`(ru); текущая en не совпадает с ru | `&НаКлиенте`; раскладка → ru |
| `ЕстьТгдд` (набрано `ЕстьNull` в ru) | `Есть`(ru) + `Null`(en) | `ЕстьNull`; раскладка остаётся ru |
| `Зкщсувгку` (ru) | целиком en | `Procedure`; раскладка → en |
| `Ghjwtlehf` (en) | целиком ru | `Процедура`; раскладка → ru |

### 7.2 Составные гибриды

Гибриды перечисляются в словаре (seed и публичный срез). Дополнительно действует **правило композиции**: `<слово из словаря> + <сегмент из latin_segments>` (или наоборот). **Измерено: список из 40 хвостов покрывает 60,6 % гибридных вхождений, 10 хвостов 51,2 %.** Остальное (латинский префикс, цифры, подчёркивания) в правило не входит и должно быть в словаре явно.

### 7.3 Решение о раскладке окна

- **Одноязычное слово**: заменить текст и переключить раскладку на ту, в которой оно записано.
- **Гибрид или слово с сигилом** (`#Область`, `&НаКлиенте`, `ЕстьNull`, `&НачалоПериода`): заменить текст и **оставить раскладку прежней**, если текущая совпадает с раскладкой хотя бы одной значимой части результата (сигил не учитывается); иначе переключить на раскладку значимой части.
- Слово, уже имеющееся в словаре в текущей раскладке, не менять.

### 7.4 Границы токена, знаки препинания, неоднозначность

Правила 6.1 действуют и здесь. Для 1С однозначные разделители: пробел, Enter, `(` `)` `=` `+` `-` `*` и клавиши, не дающие букв ни в `ru`, ни в `en` (включая `/` = `.` в ru и Shift+`/` = `,` в ru). Неоднозначные клавиши `.` `,` `;` `'` `[` `]` в русской раскладке это буквы `ю б ж э х ъ`. Поэтому нажатие такой клавиши запускает проверку: токен до неё рассматривается при гипотезе «разделитель»; если слово найдено в словаре (например `Pfghjc` → `Запрос`), срабатывает замена, а разделитель вставляется в целевой раскладке (`.`); если нет, клавиша остаётся буквой. Нескольких неоднозначных клавиш в одном токене гипотезы перебираются (не более 2⁴ вариантов); берётся единственная гипотеза, у которой все сегменты нашлись в словаре; при неоднозначности замены нет.

### 7.5 Содержимое словаря 1С

Слои по приоритету: `seed` (ключевые слова, директивы, препроцессор, пары ru/en) → платформа (MCP) → публичный срез `.bsl` → локальный лексикон. Запись: флаги (`keyword`, `directive`, `preprocessor`, `platform`, `local`, `hybrid`, `no_convert`) и частота.

### 7.6 Выбор языка программирования: radio-кнопка

Включён **ровно один** язык программирования (решение заказчика). В настройках вкладка «Programming language» показывает найденные пакеты радио-кнопками; значение пишется в `[programming_language] selected`. Следствия:
- конфликты между языками программирования исключены (правила приоритета и «конфликт при равном приоритете» из версии 1 удалены);
- переключение языка = выбор другой радио-кнопки (применяется без перезапуска: данные прежнего пакета закрываются, нового открываются);
- в режиме `auto_programming` без выбранного языка автозамена не выполняется (работает как `manual`);
- языки Rust и C++ добавляются позже как отдельные пакеты и выбираются так же; привязка к приложению это отдельная будущая задача (раздел 4).

## 10. Интеграция в демон

### 10.1 Триггер

Автозамена срабатывает на **клавише-триггере**: пробел, Enter, однозначный знак препинания (6.1, 7.4). Решение принимается синхронно в обработчике хука (десятки микросекунд). Если решение `Keep`, клавиша проходит как обычно, ничего не проглатывается. Если `Replace`:

1. клавиша-триггер **проглатывается** (вместе с её отпусканием и автоповтором, как у хоткеев);
2. в главный поток отправляется сообщение с планом замены;
3. выполняются Backspace × N, ввод слова в целевой раскладке, переключение раскладки окна (или нет, по вердикту);
4. триггер вставляется заново: пробел и Enter как нажатия клавиш (Enter как `VK_RETURN`), знак препинания как Unicode-символ, отрисованный в целевой раскладке (раскладка окна меняется асинхронно, поэтому физическую клавишу повторять нельзя).

Для Enter это важно: приложения с отправкой по Enter (чаты) получают Enter уже после исправления слова.

### 10.2 Input gate

Пока идёт замена (единицы миллисекунд), настоящие нажатия ставятся в очередь и воспроизводятся после неё (максимум 200 мс), иначе символ следующего слова может вклиниться в стёртое слово.

### 10.3 Хоткей после автозамены: продолжение цикла

После автозамены в `WordBuffer` записывается состояние цикла (последовательность раскладок и позиция), как будто слово было конвертировано хоткеем. Нажатие хоткея «convert word» **продолжает цикл** со следующей раскладки списка; после полного круга слово возвращается в исходный вид. Отдельного шага «откат» нет.

### 10.4 Блокировка автозамены клавишами (Troubleshooting)

Эпизод слова: от первой клавиши слова до клавиши-триггера. Группа «Do not switch the keyboard layout if any keys have been pressed» содержит семь флажков (в конфиге `no_switch_if_*`, по умолчанию **все включены**: ложное переключение хуже пропущенного). Если при наборе слова нажата клавиша с **отмеченным** флажком, слово «нечистое»: автозамена для него не выполняется (ручные хоткеи работают всегда).

| Флажок | Что считается нажатием | Если снят |
|---|---|---|
| Backspace | клавиша Backspace | Backspace редактирует буфер слова (как сейчас), автозамена возможна |
| Left arrow, Right arrow, Up arrow, Down arrow | стрелка | Положение каретки неизвестно: буфер **всегда сбрасывается**. Если флажок отмечен, «нечистота» сохраняется до следующей границы слова (фрагмент после перемещения каретки не конвертируется). Если снят, фрагмент считается новым словом (риск ошибочной замены принимает пользователь) |
| Delete | клавиша Delete | Delete не влияет на буфер, автозамена возможна |
| Change layout | HKL окна в фокусе отличается от HKL на момент первой клавиши слова (проверяется на каждой клавише и на триггере: покрывает Ctrl+Shift, Alt+Shift, Win+Space) | Автозамена возможна, исходной считается текущая раскладка |

Собственные переключения раскладки (при автозамене и хоткеях) нечистоты не вызывают: после них буфер начинает новый эпизод. Win+Space сбрасывает буфер всегда (как сейчас).

### 10.5 Прочие исключения

Окна из `ignored_apps`; поля паролей (стиль `ES_PASSWORD` стандартных полей, расширяется позже через UI Automation); слова с цифрами и целиком из заглавных букв (литературный режим); зажатые Ctrl/Alt/Win. При `log_level = debug` в лог пишутся режим, решение, причина и время (не сами слова).
