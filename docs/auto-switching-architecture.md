# Автопереключение раскладки: архитектурные решения

Статус: предложение на утверждение. Дата: 2026-10-25.
Исходные материалы: `prompts/prompt003.md`, `prompts/kb003.md`. Техническое задание: `docs/auto-switching-spec.md`.

## 1. Сводка решений

| № | Вопрос | Решение |
|---|---|---|
| D1 | Источник словаря 1С | **Оба источника плюс ручной seed** (список ключевых слов). Роли разные, см. раздел 2 |
| D2 | Независимость языков | Два вида пакетов (`literary`, `programming`) за общим интерфейсом `Detector`; добавление языка = добавление папки, без правки кода |

| D4 | Папки | Две корневые папки рядом с exe: `LiteraryLanguages\<код>\` и `ProgrammingLanguages\<id>\`; в каждой `pack.ini` и файлы базы |
| D5 | Загрузка | При старте читаются только `pack.ini`. Файлы данных открываются (mmap) только у включённых и активных пакетов, у отключённых освобождаются |
| D6 | Режимы | Вместо флага `autoswitch` режим `manual / auto_literary / auto_programming`; в трее подменю `Mode` |
| D7 | Кандидаты слова | Физические клавиши слова (scancode, shift) отображаются в каждую раскладку пакета; для гибридных слов добавляется сегментация «часть в одной раскладке, часть в другой» |
| D8 | Литературный режим | Каскад: правила (уникальные буквы, запрещённые биграммы) → триграммы → FST-словарь. «Текущая раскладка» всегда кандидат |
| D9 | Программистский режим | Только точное совпадение со словарём (без регистра), без n-грамм. Гибриды и сигилы (`#`, `&`) разбираются сегментацией и правилами композиции |

## 2. Что показали измерения

### 2.1 MCP-сервер `bsl-platform-context` (подключается через `.mcp.json`, `java`, stdio)

Проверено запросами:

| Запрос | Результат |
|---|---|
| `Процедура` | не найдено |
| `ЕстьNull` (метод) | не найдено |
| `Область` | первые 10 результатов это типы платформы (`ОбластьЗаголовкаДиаграммы`...); директивы `#Область` среди них нет |
| `СтрНайти` | найден (глобальный метод платформы) |

Выводы:
- Сервер отдаёт **платформенный API**: типы, глобальные методы, свойства, члены типов (`getMembers`). **Ключевых слов языка, директив компиляции, препроцессора и функций языка запросов в нём нет.**
- Имена только на русском. Английские синонимы платформы (`StrFind` и т. п.) не возвращаются.
- Нет операции «выдать всё»: только `search` (лимит 50) и `getMembers` по имени типа. Выгрузка словаря требует обхода (поиск по префиксам, затем `getMembers` по каждому найденному типу).
- Качество данных неровное (у методов типа `ТаблицаЗначений` сигнатуры скопированы с одного шаблона), но **имена** надёжны.

### 2.2 Выгрузки `.bsl` на этом компьютере

Поиск по всем дискам. `E:\1c` содержит **28 418 файлов `.bsl`**, но много копий одних и тех же конфигураций: **уникальных по содержимому 9 528 (427 МБ)**. На `D:\my_tools` лежат только 17 файлов (открытый проект V8Reader), их можно не учитывать. Статистика по уникальным файлам (комментарии и строковые литералы отброшены):

| Показатель | Значение |
|---|---|
| Токенов всего | 12,47 млн |
| Различных токенов (без учёта регистра) | 211 531 |
| Токенов, покрывающих 90 % / 95 % / 99 % вхождений | 21 654 / 54 126 / 139 012 |
| Токенов, встретившихся ≥ 2 / ≥ 5 / ≥ 20 / ≥ 100 раз | 182 331 / 105 652 / 35 044 / 8 298 |
| Гибридных (кириллица + латиница) | 5 932 различных, 86 тыс. вхождений (0,7 %) |
| С сигилом `#` или `&` | 4 672 различных, 147 тыс. вхождений (1,2 %) |
| Вхождений ключевых слов: русские формы / английские формы | 2,90 млн / 0,137 млн (английские формы около 4,5 %) |

Что из этого следует:
- **Английские формы реально используются** (`Procedure` около 13 тыс. против 129 тыс. у `Процедура`; `&AtClient` около 5,9 тыс.; `#Region` около 5,3 тыс.). Словарь обязан содержать обе формы каждого ключевого слова и директивы.
- **Гибриды в основном составные**: «русское слово + латинская аббревиатура» (`ЕстьNull`, `...XML`, `...JSON`, `...XDTO`, `Web...`). Поэтому лучше не перечислять их, а задать правило композиции «часть из словаря + латинский сегмент из короткого списка».
- Из 211 тыс. токенов большая часть это идентификаторы конкретных конфигураций. Для распознавания языка нужны единицы тысяч; остальное лучше держать отдельно (локально, см. 2.4).

### 2.3 Сравнение источников

| Критерий | Файлы `.bsl` (E:\1c) | MCP `bsl-platform-context` | Ручной seed (список ключевых слов и директив) |
|---|---|---|---|
| Ключевые слова, директивы, `#Область`, `&НаКлиенте` | да, с реальной частотой | **нет** | да (около 100–150 записей, проверяемо по документации) |
| Английские формы | да, как используются в коде | нет | да (пары ru/en задаются явно) |
| Типы, методы, свойства платформы | только то, что встретилось в коде | **да, полные и «чистые»** | нет |
| Частоты (для ранжирования и порога) | да | нет | нет |
| Идентификаторы конкретной конфигурации | да, но это приватные данные | нет | нет |
| Шум | высокий (копии, генерируемый код) | низкий | нулевой |
| Стоимость получения | дедупликация, токенизация, фильтры; обработка заняла около 6 минут | обход поиска (порядка тысяч запросов) | один раз вручную |
| Риск для публичного репозитория | **высокий**: коммерческий код, нельзя выкладывать | низкий: только имена из документации платформы | нет |

**Вердикт: берём оба источника и добавляем seed.**
- **Seed** определяет язык как таковой: ключевые слова, директивы компиляции, препроцессор, пары ru/en, список латинских сегментов для гибридов. Это ядро, оно маленькое и проверяется глазами.
- **MCP** даёт полный и чистый перечень имён платформы (типы, глобальные методы, свойства).
- **Файлы `.bsl`** дают частоты и нужны для двух целей: (а) ранжирование и порог отсечения; (б) необязательный **локальный лексикон проекта**: идентификаторы пользователя, которые он набирает каждый день.

### 2.4 Политика поставки словарей (важно для GitHub)

- В репозиторий и в релиз попадает **только публичный слой**: seed + имена из MCP + токены из `.bsl`, которые есть в seed/MCP или встречаются в **не менее K независимых конфигурациях** (K по умолчанию 3, после дедупликации копий).
- **Локальный лексикон проекта** (идентификаторы из своей базы) строится командой `dictgen` на машине пользователя, кладётся в `ProgrammingLanguages\1c\local\` и добавлен в `.gitignore`. Он подключается как второй слой с более низким приоритетом.
- Для литературных языков нужно проверить лицензии корпусов до коммита (раздел 11).

## 3. Общая схема

```
 клавиатура ─► LL-хук (поток демона)
                 │ физические клавиши слова (scancode+shift)  ── уже есть: WordBuffer
                 ▼
          конец слова? (пробел)  ──нет──► продолжаем набор
                 │да
                 ▼
          Engine (режим из конфига)
           ├─ manual            → ничего (только хоткеи)
           ├─ auto_literary     → LiteraryDetector  ─┐
           └─ auto_programming  → ProgrammingDetector┤
                                                     ▼
                                   Verdict { Keep | Replace{ text, layout? } }
                 ▼
          Replace → inject (Backspace×N, Unicode-текст, смена раскладки или нет)
                      ── уже есть: send_backspaces / send_text / switch_layout
```

Что используется из существующего кода без изменений: `core::word::WordBuffer` и `KeyStroke`, `core::layout` (`enumerate`, `resolve_layouts`, `key_to_char`), `core::i18n::Translator`, `daemon::inject`. Новое: пакеты, детекторы, режимы, «input gate».

### Модули

| Крейт / модуль | Содержимое | WinAPI |
|---|---|---|
| `lite-switcher-core` (есть) | конфиг, раскладки, буфер слова, i18n, хоткеи; добавляются поля `mode`, секции `[literary_language]`, `[programming_language]` | да |
| **`lite-switcher-lang` (новый)** | `pack` (манифест, обнаружение, реестр), `format` (чтение/запись `words.fst`, `ngram.bin`), `literary`, `programming`, трейты `Detector`, `KeyRenderer` | **нет** (тестируется на любой ОС статическими таблицами раскладок) |
| **`lite-switcher-dictgen` (новый, bin)** | сборка пакетов из корпусов, `.bsl`, дампа MCP, seed | нет |
| `lite-switcher` (демон) | `engine.rs`: связывает хук, реестр пакетов и замену; подменю трея | да |
| `lite-switcher-settings` | вкладки «Literary language» и «Programming language», выбор режима | да |

Набросок интерфейсов (для согласования, не окончательный код):

```rust
pub trait KeyRenderer { fn render(&self, key: &KeyStroke, layout: &Layout) -> Option<char>; }

pub struct WordContext<'a> {
    pub keys: &'a [KeyStroke],
    pub current: &'a Layout,        // раскладка, активная при наборе
    pub layouts: &'a [Layout],      // установленные раскладки пакета
    pub previous: Option<&'a Previous>, // язык предыдущего слова (разрешение ru/uk)
}

pub enum Verdict {
    Keep,
    /// `layout: None` - раскладку окна не менять (двуязычные операторы 1С).
    Replace { text: String, layout: Option<Layout>, reason: Reason },
}

pub trait Detector: Send + Sync {
    fn decide(&self, ctx: &WordContext, renderer: &dyn KeyRenderer) -> Verdict;
}
```

## 4. Режимы и интерфейс

- Конфиг: `[common] mode = manual | auto_literary | auto_programming`. Старый ключ `autoswitch` читается один раз при миграции (`true` → `auto_literary`, `false` → `manual`) и больше не записывается.
- Трей: пункт «Auto-switching» заменяется пунктом **«Mode»** с подменю из трёх взаимоисключающих пунктов: «auto literary», «auto programming», «manual» (с галочкой на текущем). Тексты идут через `Language\*.ini` (русский и украинский переводы обязательны).
- Хоткеи ручной конвертации (слово, выделение, регистр) работают **во всех режимах**, как в Punto.
- Хоткей `toggle_autoswitch` сохраняет имя ключа и меняет смысл: переключает между `manual` и последним автоматическим режимом.
- Настройки: в Common / General выбор режима; две новые вкладки **«Literary language»** и **«Programming language»** со списками найденных пакетов и флажками. Неактивные (нет нужной раскладки) показываются серыми с причиной.
- Конфиг: `[literary_language] enabled = auto | ru,uk,en` (по умолчанию `auto` = все найденные) и `[programming_language] enabled = 1c` (по умолчанию пусто: языки программирования включаются **только явно**).

### 5.2 Манифест `pack.ini` (общий формат, INI как в остальном проекте)

```ini
[pack]
kind = literary            ; literary | programming
code = ru                  ; идентификатор пакета (имя папки)
name = Russian             ; показывается в списке
format = 1                 ; версия формата данных
version = 3                ; версия содержимого

[layouts]
match = ru                 ; literary: префиксы локали (ru -> ru-RU...)
require = ru,en            ; programming: все перечисленные должны быть установлены
roles = ru:native, en:latin  ; programming: какая раскладка «своя», какая латинская

[files]
words = words.fst
ngram = ngram3.bin         ; только literary
exceptions = exceptions.txt

[literary]
alphabet = абвгдеёжзийклмнопрстуфхцчшщъыьэюя
unique_letters = ыэъё      ; буквы, которых нет в «соседнем» языке (для ru/uk)
min_word_len = 3

[programming]
case_sensitive = false     ; 1С нечувствительна к регистру, Rust и C++ - чувствительны
sigils = #,&
latin_segments = Null,XML,JSON,XDTO,Web,HTTP
```

(Комментарии после `;` в примере только для пояснения: в реальном файле их нужно писать на отдельных строках, как в `config.ini`.)

### 5.3 Обнаружение и активация

1. При старте (и при перезагрузке конфига) демон сканирует обе корневые папки и читает **только `pack.ini`**: десятки килобайт, миллисекунды.
2. **Литературный пакет активен**, если он включён в конфиге и в Windows установлена хотя бы одна раскладка с подходящим префиксом локали. Пример: найдено 10 европейских пакетов, установлено 3 раскладки, значит активны 3, остальные 7 «неактивные» (манифест прочитан, данные не открыты).
3. **Программистский пакет активен**, если он явно включён в `[programming_language]` и **все** раскладки из `require` установлены. Для 1С нужны русская и английская.
4. Для активных пакетов открываются файлы данных (mmap). При отключении или удалении раскладки данные закрываются. Загрузка выполняется в фоновом потоке, готовый набор подменяется атомарно (`Arc`), поток хука никогда не ждёт загрузки.
5. Пакет с неподдерживаемым `format`, повреждённым файлом или несовпадающей контрольной суммой пропускается с записью в лог; программа продолжает работать.

## 6. Алгоритм литературного режима

Опирается на `kb003.md`. Вход: физические клавиши слова и текущая раскладка.

1. **Кандидаты.** Слово отображается в каждую раскладку активных пакетов по предвычисленной таблице. Текущая раскладка тоже кандидат.
2. **Правила** (почти бесплатно, отсекают большинство случаев):
   - уникальные буквы: `і ї є ґ` бывают только в `uk`, `ы э ъ ё` только в `ru`;
   - запрещённые сочетания (`ъы`, `ьь`...) делают кандидата невозможным;
   - если слово в текущей раскладке не содержит невозможных сочетаний, а другие кандидаты их содержат, остаётся текущее.
3. **Триграммы.** Для каждого оставшегося кандидата считается сумма квантованных логарифмов вероятностей триграмм (с границами слова). Выбирается лучший; переключение происходит, если он лучше текущего **не меньше чем на порог** (порог настраивается в манифесте). Это даёт приоритет «не трогать».
4. **Словарь (FST)** вызывается только при малом отрыве между двумя лучшими. Слово из словаря пересиливает n-граммы; слово из `exceptions.txt` (аббревиатуры, имена) блокирует замену.
5. **ru против uk.** Общие буквы дают ничью; решают уникальные буквы, затем триграммы, затем язык предыдущего слова (контекст хранится на окно, живёт ограниченное время).
6. **Когда срабатывать.** На пробеле, не раньше чем на 3-м символе (`min_word_len`). Не срабатывать на слова с цифрами, целиком из заглавных букв (аббревиатуры), в окнах из списка `ignored_apps`, при зажатых Ctrl/Alt/Win.
7. **Принцип.** Ложное переключение хуже пропущенного: все пороги выбираются по метрике ложных срабатываний (ТЗ, раздел 7).

## 7. Алгоритм программистского режима (1С)

Мотивация и числа см. 2.2. Принципы: **только точное совпадение со словарём**, **без регистра** (1С нечувствительна), **никаких n-грамм** (в коде слишком много идентификаторов, n-граммы дали бы ложные срабатывания).

### 7.1 Кандидаты и сегментация

Ключ слова: последовательность физических клавиш `k0..kn`. Для двух раскладок пакета (`ru`, `en`) строятся кандидаты:

- **целиком**: `render(k0..kn, ru)` и `render(k0..kn, en)`;
- **со сменой раскладки внутри слова** (гибриды): для каждой точки разреза `i` строки `render(k0..ki, A) + render(ki..kn, B)` для пар `A≠B`. Для слова из `n` клавиш это `2·(n+1)` строк.

Каждая строка ищется в словаре без учёта регистра. Один механизм покрывает все случаи из задания:

| Набрано (раскладка ru, как нажаты клавиши) | Кандидат | Результат |
|---|---|---|
| `№Область` | разрез после 1-й клавиши: `#`(en) + `Область`(ru) | `#Область`; раскладка окна остаётся ru |
| `?НаКлиенте` (Shift+7 в ru даёт `?`) | разрез после 1-й клавиши: `&`(en) + `НаКлиенте`(ru) | `&НаКлиенте`; раскладка остаётся ru |
| `&Yfrkbtynt` (всё набрано в en) | разрез после 1-й клавиши: `&` + `НаКлиенте`(ru); текущая en не совпадает с ru | `&НаКлиенте`; раскладка → ru |
| `ЕстьТгдд` (набрано `ЕстьNull` в ru) | разрез после 4-й клавиши: `Есть`(ru) + `Null`(en) | `ЕстьNull`; раскладка остаётся прежней |
| `Зкщсувгку` | целиком en | `Procedure`; раскладка → en |
| `Ghjwtlehf` (набрано в en) | целиком ru | `Процедура`; раскладка → ru |

### 7.2 Составные гибриды

В коде гибриды в основном составные (`...XML`, `...JSON`, `...XDTO`, `Web...`, `ЕстьNull`). Поэтому дополнительно к перечисленным в словаре гибридам действует **правило композиции**: строка = `<слово из словаря в раскладке A>` + `<латинский сегмент из списка latin_segments>`, либо наоборот. Это распознаёт и ещё не встречавшиеся комбинации, не раздувая словарь.

### 7.3 Решение о раскладке окна

- **Одноязычное слово** (целиком в одной раскладке): заменить текст и **переключить раскладку** на ту, в которой слово записано.
- **Гибрид или оператор с сигилом** (`#Область`, `&НаКлиенте`, `ЕстьNull`, `&НачалоПериода`): заменить текст и **оставить раскладку окна прежней** (требование заказчика), если текущая раскладка совпадает с раскладкой хотя бы одной значимой части результата (сигил `#`/`&` в расчёт не берётся). Если не совпадает (например, `&НаКлиенте` целиком набрано в en, а значимая часть русская), раскладка переключается на раскладку значимой части.
- Если слово **уже верно в текущей раскладке** (есть в словаре) ничего не делать.

### 7.4 Границы токена и неоднозначные клавиши

Клавиши `.` `,` `;` `'` `[` `]` в русской раскладке дают буквы `ю б ж э х ъ`. Поэтому «точка» между `Запрос` и `Выполнить` может оказаться буквой `ю`. Решение MVP: токеном считается часть слова **после последнего однозначного разделителя** (пробел, `(`, `)`, `=`, `+`, `-`, `*` и ещё несколько клавиш, одинаковых в обеих раскладках 1С-пакета). Неоднозначные клавиши рассматриваются как гипотезы «буква» и «разделитель» (решётка гипотез, не более 2^4 вариантов); берётся гипотеза, у которой все сегменты нашлись в словаре. Если однозначного ответа нет, замены нет.

### 7.5 Что в словаре 1С

Слои (по приоритету): `seed` (ключевые слова, директивы, препроцессор, пары ru/en) → платформа из MCP (типы, методы, свойства) → частотные токены из `.bsl` (публичный срез) → локальный лексикон проекта (необязательный, не публикуется). Каждая запись хранит флаги (`keyword`, `directive`, `preprocessor`, `platform`, `local`, `hybrid`, `no_convert`) и частоту.

### 7.6 Несколько языков программирования сразу

Список с флажками разрешает включить несколько пакетов (1С, Rust, C++). Но у разных языков слова пересекаются (`for`, `if`), а кириллическая «ерунда» может оказаться английским ключевым словом. Правила: порядок в списке = приоритет; слово принимается, только если его **нет** в словаре пакета в текущей раскладке; конфликт между пакетами при равном приоритете значит «не менять». Привязка к приложению (например, `1cv8.exe` → 1С, `Code.exe` → Rust) это следующий шаг и в этом этапе не делается.

## 8. Хранение данных и скорость

| Данные | Формат | Размер (оценка) | Поиск |
|---|---|---|---|
| Таблица «клавиша → символ» на раскладку | массив `char` по индексу `[shift][scancode]` в памяти, строится при старте и при смене списка раскладок | единицы КБ | O(1), доли микросекунды на слово |
| Триграммы | плоский массив `u8` (квантованный логарифм), индекс `(a·A + b)·A + c`, `A` = размер алфавита + граница слова; файл `ngram3.bin` с заголовком (magic, версия, `A`) | ru: 34³ ≈ 39 КБ; en: 27³ ≈ 20 КБ | O(1) на символ |
| Словарь | `words.fst` (`fst::Map`, значение `u32` = флаги + частота), открывается через mmap | 1С (публичный слой, десятки тысяч слов): сотни КБ; литературный язык: единицы МБ для частотного среза 300–500 тыс. форм | O(длина слова), порядка сотен наносекунд |
| Исключения | `exceptions.txt` → маленький `fst::Set` в памяти | КБ | O(длина слова) |

- **Bloom-фильтр в первой версии не нужен**: FST и так быстрый. Решение пересматривается только по результатам бенчмарка.
- **Память**: открываются только данные включённых активных пакетов; mmap означает, что физически читаются лишь затронутые страницы. Бюджет: не более +10 МБ к текущему процессу при ru+uk+en+1С.
- **Скорость**: бюджет на одно слово не более 1 мс (p99, release, слово до 40 клавиш); ожидаемо десятки микросекунд (оценка, подтверждается бенчмарком из ТЗ).
- **Индексы и версии**: каждый файл данных имеет заголовок с версией формата; несовпадение значит пакет пропускается. Контрольные суммы в манифесте.
- Предвычислять ключи словаря по раскладкам (индекс «последовательность клавиш → запись») не берём: он зависит от установленных раскладок и усложняет кэш. Достаточно рендера кандидатов и поиска по строке (раздел 7.1).

## 9. Инструмент сборки словарей `dictgen`

Подкоманды (один бинарник, общий код форматов с `lite-switcher-lang`):

| Команда | Вход | Выход |
|---|---|---|
| `literary --lang ru --corpus <файлы/словарь> --out LiteraryLanguages\ru` | список слов с частотами, корпус | `words.fst`, `ngram3.bin`, `pack.ini` |
| `programming --lang 1c --seed seed.txt --mcp <дамп> --bsl <папка> [--min-projects 3] --out ...` | seed, дамп MCP, выгрузки `.bsl` | `words.fst`, `pack.ini` |
| `programming --lang 1c --bsl <папка> --local --out ...\local` | только свои `.bsl` | локальный лексикон |
| `mcp-dump --config .mcp.json --out dump.json` | сервер из `.mcp.json` | перечень типов, методов, свойств (только имена) |
| `eval --pack <папка> --testset <файл>` | размеченный список слов | точность, полнота, ложные срабатывания |

Особенности обработки `.bsl` (по результатам измерений): дедупликация файлов по хэшу содержимого (28 418 → 9 528), отбрасывание комментариев и строковых литералов, учёт токенов с сигилами, документная частота по «независимым конфигурациям» для публичного среза. Выгрузка MCP обходит поиск по префиксам и `getMembers`; результат кэшируется в файл и коммитится как список имён.

## 10. Интеграция в демон

- **Триггер.** Конец слова = пробел (в первой версии; Enter и знаки препинания позже). Решение принимается в обработчике хука за микросекунды; если нужна замена, пробел **задерживается** (проглатывается) и вставляется вместе с заменой.
- **Замена.** Механизм тот же, что у ручной конвертации: Backspace × N, Unicode-текст, переключение раскладки (или нет). Хвостовой пробел входит в замену.
- **Input gate.** Пока идёт замена (единицы миллисекунд), настоящие нажатия, пришедшие в этот промежуток, ставятся в очередь и воспроизводятся после неё (максимум 200 мс), иначе возможна гонка: символ следующего слова вклинится в стёртое слово.
- **Откат.** Первое нажатие хоткея «конвертировать слово» сразу после автозамены возвращает исходный текст; следующие нажатия продолжают обычный цикл. Состояние хранится в `WordBuffer` (исходные клавиши и раскладка).
- **Исключения.** Окна из `ignored_apps`; поля паролей (стиль `ES_PASSWORD` стандартных полей, расширяется позже через UI Automation); слова с цифрами и целиком из заглавных букв (литературный режим).
- **Лог.** При `log_level = debug` пишутся решение, причина и время (не сами слова).

## 11. Риски и открытые вопросы

| № | Риск или вопрос | Предложение |
|---|---|---|
| R1 | Неоднозначные клавиши (`.` / `ю`) в 1С-токенах | Решётка гипотез (7.4), в MVP при сомнении не менять |
| R2 | Приватные данные в словаре: выгрузки E:\1c коммерческие | Публичный слой только по правилу K≥3 конфигураций; локальный слой не публикуется (2.4) |
| R3 | Лицензии корпусов для литературных языков (Wikipedia CC BY-SA, OpenSubtitles имеет ограничения, Hunspell LGPL/MPL) | Выбрать источники и зафиксировать лицензии **до** коммита словарей |
| R4 | Размер бинарных словарей в git | Хранить частотный срез; при превышении 10–20 МБ на пакет перейти на Git LFS или на сборку при релизе |
| R5 | Ложные срабатывания | Пороги по метрике FP ≤ 0,1 %; откат хоткеем; режим `manual` всегда доступен |
| R6 | Гонка ввода во время замены | Input gate (раздел 10) |
| R7 | Приложения, где «Backspace + Unicode» работает плохо (часть терминалов, игры) | Те же ограничения, что у ручной конвертации; `ignored_apps` и `key_delay_ms` |
| R8 | Английские синонимы платформы отсутствуют в MCP | Seed и частоты `.bsl`; при необходимости добавить пары вручную |

Вопросы к заказчику (нужно решить до или в начале реализации; предложенные варианты в скобках):

1. Названия корневых папок: `LiteraryLanguages` и `ProgrammingLanguages` (подходит?).
2. Триггер автозамены: только пробел или ещё Enter и знаки препинания (пробел).
3. Поведение хоткея сразу после автозамены: откат, затем цикл (да).
4. Несколько языков программирования одновременно и привязка к приложению (одновременно с приоритетами; привязка позже).
5. Откуда брать корпуса для ru/uk/en и какие лицензии допустимы (Hunspell/OpenCorpora/Wikipedia, после проверки лицензий).
6. Коммитить ли бинарные словари в репозиторий (да для частотных срезов; локальный лексикон проекта никогда).
7. Режим по умолчанию после обновления: `manual` (чтобы автозамена не включилась неожиданно).
